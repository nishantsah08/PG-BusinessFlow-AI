# EventViewer State Behaviors

Conforms strictly to the 5 mandatory UI states via `StateWrapper`.

## 1. loading
- **Trigger:** Initial mount or manual refresh triggered by the user via the `RefreshCcw` button.
- **Behavior:** Renders the standard `StateWrapper` spinner. Note: Background silent polling operations do **not** trigger the visual `loading` state to prevent UI jitter.

## 2. success
- **Trigger:** `apiClient` returns `success: true` with an array length > 0.
- **Behavior:** `StateWrapper` renders the chronologically sorted event cards.

## 3. empty
- **Trigger:** `apiClient` returns `success: true` but the `events` array is length 0.
- **Behavior:** `StateWrapper` renders "No system events captured yet" illustration.

## 4. error
- **Trigger:** `apiClient` returns `success: false` or throws an exception during a fetch operation.
- **Behavior:** `StateWrapper` visually displays the `errorMsg`. Further background polling continues if the interval is active, which may self-heal the state.

## 5. retry
- **Trigger:** The 'Retry' button generated by `StateWrapper`.
- **Behavior:** Invokes `fetchEvents(false)`, triggering a hard UI `loading` state while re-attempting the network request.

# ChatPanel State Behaviors

The `ChatPanel` strictly conforms to the 5 mandatory UI states via `StateWrapper` and internal logic.

## 1. empty
- **Trigger:** Initial render, or when the user explicitly clears the local array using the trash icon.
- **Behavior:** Renders the "Send a message to MasterAI to begin." empty message. Form remains active.

## 2. loading
- **Trigger:** User submits a message.
- **Behavior:** The input form is disabled. A bouncy loading indicator is appended to the bottom of the conversation feed. 

## 3. success
- **Trigger:** `apiClient` returns `success: true` with a valid response payload.
- **Behavior:** `StateWrapper` renders children. The AI response is appended to the local feed. Input is re-enabled.

## 4. error
- **Trigger:** `apiClient` returns `success: false` or throws an exception.
- **Behavior:** `StateWrapper` visually displays the `errorMsg`. The optimistically added user message is popped from the array.

## 5. retry
- **Trigger:** The 'Retry' button generated by `StateWrapper` during an `error` state or the 'Refresh' button in an `empty` state.
- **Behavior:** Resets component status back to `empty`. Note: Unlike a data table, `ChatPanel` does not replay the failed message automatically; it merely resets the visual state to allow the user to try typing again.
